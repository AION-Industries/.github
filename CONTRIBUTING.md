# Contributing to AION Technologies

Thank you for your interest in contributing to AION Technologies projects.

## Code of Conduct

We are committed to providing a welcoming and respectful environment. Please be constructive, professional, and respectful in all interactions.

## Getting Started

1. Fork the repository you want to contribute to.
2. Create a feature branch from `main`:
   - `feat/<short-description>`
   - `fix/<short-description>`
   - `docs/<short-description>`
   - `refactor/<short-description>`
3. Make your changes in focused, logical commits.
4. Open a Pull Request against `main`.

## Commit Messages

We follow Conventional Commits:

- `feat:` new feature
- `fix:` bug fix
- `docs:` documentation
- `refactor:` code refactoring
- `test:` tests
- `perf:` performance
- `build:` build system
- `ci:` CI/CD
- `chore:` maintenance

Format: `type(scope): description`

Example: `feat(auth): implement secure login`

## Pull Requests

- Keep PRs focused and reasonably sized.
- Include a clear description of the change and its motivation.
- Reference related issues when applicable.
- Ensure tests pass and code is reviewed before merge.
- Do not force-push to shared branches.

## Branching

- `main` is the stable, validated branch.
- Do not push incomplete work directly to `main`.
- Use the branch prefixes listed above.

## Security

Never include secrets, API keys, tokens, passwords, or private data in commits, issues, or pull requests. Report security concerns privately (see SECURITY.md).

## Questions

For questions and discussions, use GitHub Discussions or open an issue in the relevant repository.
